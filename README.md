# Ancient UNIX風サブセットOS

MMUを前提とせず、小規模な環境でUNIX風のシェルと基本的なOS機能を動かすことを目指す個人開発プロジェクトです。UNIX V7を外部機能の参考にしつつ、必要な機能を選んでゼロから実装します。

> 本プロジェクトはUNIXのソースコードを使用しません。V7とのバイナリ互換性や完全なAPI互換性も目標としていません。

## 特長

- **小規模・MMU非依存**: Raspberry Pi Pico（Cortex-M0）およびMC68000級CPUを想定し、必要メモリ2 MB未満、ソースコード6,000行以下を目安に設計します。
- **シェルを中心に機能を選択**: 最終目標は`ash`(に似た独自シェル)が実用に耐える水準で動くことです。プロセス生成、ファイル操作、リダイレクト、パイプ、シグナルなど、段階的に必要な機能を整えます。
- **独自のプロセス生成方式**: `fork()`/`exec()`ではなく、実行ファイルのロードと新規プロセス生成をまとめた`spawn()`を採用します。
- **UNIX風の外部機能と柔軟な内部設計**: V7などを機能水準の参考にしますが、内部構造やアルゴリズムを歴史的実装に合わせることは求めません。
- **単純さと移植性を重視**: シングルユーザー・単一ファイルシステムを前提に、必要性の低い機能や汎用化を抑えます。

## 実装方針

### アーキテクチャ

カーネルはモノリシック構成とし、システムコールの入口・ディスパッチ、HAL、プロセス管理、メモリ管理、ファイルシステム、パイプなどのIPC、シグナルを責務ごとに分けます。システムコールは引数検証や変換、内部APIへの接続を担う薄い層とし、実際の状態管理や資源管理はカーネル内部APIに置きます。

ハードウェア依存機能はHALを介して利用します。ターゲットはビルド時に選択し、実行時にバックエンドを切り替える仕組みは設けません。初期開発ではホスト環境を使って検証し、ターゲット固有のドライバ作成から始めない方針です。

### ファイルシステムとプロセス

ファイルシステムはFAT/inodeハイブリッド方式、階層化ディレクトリあり、キャッシュなしの直接I/Oを計画しています。プロセス生成時にはファイルシステムから実行ファイルを読み込み、子プロセスは呼び出し元のオープン済みファイルディスクリプタを継承します。

メモリ管理はプロセスイメージやスタックの確保に必要な範囲に絞り、スワップやページングは導入しません。ホスト実装でホストOSの機能を使う場合も、ターゲットで実現できないプロセスモデルを持ち込まないようにします。

### 段階的な開発計画

仕様では、依存関係とホスト環境での検証しやすさを考慮して、次の順に進めます。

1. 独自ファイルシステムとシステムコールディスパッチの土台
2. ファイルI/O、ディレクトリ操作、リダイレクト相当の機能
3. `spawn()`、`exit()`、`wait()`によるプロセス生成と終了管理
4. `sleep()`とパイプによる協調スケジューリング・プロセス間通信
5. `signal()`、`kill()`と時間計測
6. 実際のシェル（`ash`の移植または簡易実装）

ホスト上の疑似ユーザープログラムは、ファイル関連機能を早く検証するための中間段階です。最終的には実際の`spawn()`で実行ファイルを起動する構成を目指します。仕様上の最終目標はLv.2（23個のシステムコールを中心とする機能水準）で、実機・エミュレータへの移植はその後の任意マイルストーンです。
