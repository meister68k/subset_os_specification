# 極小 SysV init 仕様書

| 項目 | 内容 |
|---|---|
| 文書ID | INIT-SPEC-001 |
| 版 | 0.1（初版設計・一部暫定） |
| 対象 | UNIXサブセットOSの `/sbin/init` と `/etc/inittab` |
| 参照 | ilibc APIリファレンスマニュアル ILIBC-REF-001 v0.1 |
| 状態 | 構文の合意事項を反映。エラー処理の一部は推奨案として明示 |

## 1. 目的と範囲

UNIX System V の `/etc/inittab` 形式を借用した、順次実行型の極小 init を提供する。起動時に `/etc/inittab` を先頭から読み、各有効行の `process` を起動し、終了を待ってから次の有効行へ進む。

初版では以下に限定する。

- `action` は `wait` のみ。
- `runlevels` フィールドは存在するが、内容を無条件で無視する。
- `respawn`、ランレベル制御、再読込、常駐監視は実装しない。
- 開発段階では、全エントリ処理後に PID 1 の init が終了することを許容する。
- 動的メモリ確保および汎用シェル構文解析は不要とする。

本書の主眼は設定の読み込み・解析・エラー処理である。プロセス起動API、子プロセス管理、シグナルの具体的ABI・実装は現段階の対象外。

## 2. 設定ファイル形式

ファイルパス：`/etc/inittab`。

1行につき1エントリとし、SysV由来の4フィールド形式を維持する。

```text
id:runlevels:action:process
```

最初の **3個の `:`** のみをフィールド区切りとして扱う。4番目のフィールド中の `:` は通常の文字とする。4フィールドを満たさない行は構文エラー。

例：

```ini
# Startup sequence
boot::wait:/bin/echo Starting
mount:23:wait:/bin/mount /dev/hd0 /mnt
script:arbitrary:wait:/bin/sh /etc/rc
```

### 2.1 フィールド規則

| フィールド | 規則 |
|---|---|
| `id` | 必須。長さ1〜16文字。17文字以上は構文エラー。実行処理では参照しない。 |
| `runlevels` | 任意の文字列（空文字を含む）を許容し、読み飛ばす。ランレベルの解釈・検査を行わない。 |
| `action` | 文字列 `wait` に完全一致する場合のみ有効（大小文字を区別）。 |
| `process` | 必須。空白を除いた結果としてコマンドが1つ以上必要。 |

`id` の文字種は初版で追加制限しない（長さのみ検査）。`id` の重複検出は初版の対象外とする（暫定）。

`runlevels` は内容が何であっても正常扱いとするが、形式上の `:` を省略してはならない。

### 2.2 行の規則

- 文字コードはASCIIを基本とする。
- 改行はLFおよびCRLFを受け付ける。
- 空行、スペース・タブだけの行を無視する。
- 行頭のスペース・タブを読み飛ばした先頭文字が `#` ならコメント行として無視する。
- 行末（インライン）コメントは解釈しない。`#` はそれ以外の場所では通常の文字とする。
- エントリの先頭空白は読み飛ばすが、フィールドの前後を一般的にはトリミングしない。`process` の前後の空白だけは引数分割時に無視する。
- 行本文の最大長は127文字（改行文字は含めない）。超過行は構文エラーとし、同じ物理行の残りを読み捨てる。
- 入力に埋め込みNULがあった場合は不正。ただし既存のNUL終端文字列型入力APIだけでは確実に検出できないため、厳密な検出手段は未確定（§7参照）。

### 2.3 `process` の字句規則

`process` をスペース（`0x20`）とタブ（`0x09`）で分割し、先頭から `argv[0]`, `argv[1]`, ... とする。

- 連続するスペース・タブは単一の区切りとして扱う。
- 前後のスペース・タブは無視する。
- 最大8引数（`argv[0]`を含む）。超過は構文エラー。
- `'` と `"` は **通常文字**。引用符としてのグループ化・除去はしない。
- バックスラッシュによるエスケープ、環境変数展開、ワイルドカード展開、パイプ、リダイレクト、コマンド置換、シェル起動の暗黙化は行わない。
- 特別な構文が必要なら、設定に明示的に `/bin/sh ...` を指定する。

例：

```ini
test::wait:/bin/echo "hello world"
```

分割結果：

```text
argv[0] = /bin/echo
argv[1] = "hello
argv[2] = world"
argv[3] = NULL
```

## 3. 逐次解釈と実行

1. `/etc/inittab` をオープンする。
2. 先頭から1物理行ずつ取得する。
3. 行長・改行・コメントを処理し、4フィールドへ分割する。
4. `id` の長さ、`action`、`process`、引数数を検査する。`runlevels` の値は無視する。
5. 有効なエントリは `process` を直接起動し、その終了を待つ。`spawn()`は`nullptr, 0`を指定して全open fdを継承し、標準入出力を含むinitのFD環境を維持する。**次のエントリを起動するのは終了待ち後**とする。
6. EOFまで繰り返す。
7. ファイルを閉じ、init 自身は終了してよい。

初版ではエントリを蓄積せず、1行分の固定長バッファと固定長 `argv` 配列で順次処理する。

`spawn()` / `wait()`のAPIと失敗規約は[`../kernel/spawn_wait_implimentation_spec.md`](../kernel/spawn_wait_implimentation_spec.md)に従う。各エントリの起動には全FD継承(`inherit_fds == nullptr`, `inherit_fd_count == 0`)を指定する。

## 4. エラー処理

基本方針はSysV initに倣い「不正な設定行はその行だけ無視して可能な限り続行する」。ただしPID 1の終了を許容する開発段階のため、致命的I/Oエラーは終了可能とする。

以下は直前の検討で提示された **推奨案** であり、ユーザー確認前の暫定規定とする。

| 事象 | 暫定動作 |
|---|---|
| `/etc/inittab` が開けない | 診断を出力して異常終了 |
| 読み込み途中のI/Oエラー | 診断を出力して異常終了 |
| 行長超過 | 当該物理行の残りを読み捨て、次行へ |
| フィールド不足、id長不正、action不正、process空、引数数超過 | 当該行をスキップ、次行へ |
| `runlevels` の内容 | 無条件で無視し、エラーにしない |
| `id` 重複 | 検査しない |
| プロセス起動失敗 | 診断を出して次行へ（実行API決定後に確定） |
| `wait` 対象が非0終了 | 次行へ（init自身のエラーとはみなさない） |
| EOF | 正常な読み込み終了 |

### 4.1 診断

- 可能な限り標準エラー出力（fd=2）に記録する。
- 構文エラーはファイル名・行番号・簡潔な原因を含める。
- SysV互換のsyslogは要求しない。
- 診断出力自体の失敗で再帰的にエラー処理しない。

例：

```text
init: /etc/inittab:4: invalid action
```

### 4.2 init終了ステータス（**未確定・推奨B案**）

- すべての行が問題なく処理できた場合：`0`。
- 構文エラー等の回復可能なエラーが1件以上あれば、処理を最後まで継続した上で：`1`。
- オープン失敗や読み込みエラーなど致命的なエラー：`1`。
- 子プロセス自身の非0終了は、initの終了ステータスに反映しない。

これは従来の常駐SysV initの規則ではなく、テスト容易性を優先した本OS独自仕様案である。

## 5. ilibc/OSの依存関係

libc追加APIは原則不要。既存のILIBC-REF-001 v0.1に記載の以下の関数を使用する。

| 処理 | API | 備考 |
|---|---|---|
| 行入力 | `ilibc::gets(line, fd, ilibc::clear_errno(err))` | 配列容量を推定する独自の安全な `gets`。改行を保持する。 |
| `:`の検索 | `std::strchr()` | 行バッファ内をNULで破壊的に分割。 |
| アクション比較 | `std::strcmp()` | `wait` の完全一致に使用。 |
| 行末処理、id長の検査 | `std::strlen()` | 必要に応じて使用。 |
| 診断 | `ilibc::fprint_f<fmt>()` | 書式指定子は `%d`, `%s`, `%%` のみで十分。 |

ファイルの `open()`、`close()`、将来のプロセス起動・待機・終了は **OSのシステムコールラッパ** とし、ilibc APIの追加とは区別する。

**実機I/Oバックエンドの課題**：添付マニュアル上、`<cstdio>` の `ILIBC_IO_BACKEND_POSIX` はホスト用、`ILIBC_IO_BACKEND_CUSTOM` は予約のみであり、initをターゲットOSで動かすには `gets` / 診断出力をOSの `read` / `write` につなぐ実装が必要。現行公開APIが実機で既にリンク可能であることは保証されていない。

## 6. 構文例と期待結果

| 入力 | 結果 |
|---|---|
| `boot::wait:/bin/echo ok` | 有効 |
| `boot:123:wait:/bin/echo ok` | 有効。`123` は無視 |
| `boot:abc:wait:/bin/echo ok` | 有効。`abc` は無視 |
| `boot::WAIT:/bin/echo ok` | 不正。actionは完全一致 |
| `boot::respawn:/bin/sh` | 不正。未対応action |
| `::wait:/bin/echo ok` | 不正。idが空 |
| `abcdefghijklmnop::wait:/bin/echo ok` | 有効。idは16文字 |
| `abcdefghijklmnopq::wait:/bin/echo ok` | 不正。idは17文字 |
| `boot:wait:/bin/echo ok` | 不正。フィールド不足 |
| `boot::wait:` | 不正。processが空 |
| `boot::wait:   ` | 不正。processに単語がない |
| `boot::wait:/bin/echo "a b"` | 有効。`"a` と `b"` は別引数 |

## 7. 実装前に残る論点

1. **エラー時の終了ステータス**：暫定B案（構文エラーを記録し、最後まで処理してから `1`）を正式採用するか。
2. **I/Oバックエンド**：`ILIBC_IO_BACKEND_CUSTOM` 等を実装してターゲットOSのFD読み書きを利用可能にする。
3. **埋め込みNULの検出**：`gets` は文字数を返さないため、厳密検査は困難。対象を「信頼できるテキスト設定ファイル」として扱うか、入力処理にバイト長を持たせるか決める。
4. **最大行長の境界処理**：改行を保持する `gets` と127文字の本文制限を両立する。特に127文字ぴったり、CRLF、改行なしEOF、および超過行の読み捨てをテストする。
5. **プロセス起動・待機ABI**：OS側が提供できた段階で確定する。

## 8. 非目標

ランレベル、`initdefault`、`sysinit`、`once`、`respawn`、`ctrlaltdel`、`powerfail`、`/etc/inittab` の再読み込み、プロセス監視・再起動、シェル互換の展開、syslog連携、一般的なSysV initとの完全互換は対象外。
