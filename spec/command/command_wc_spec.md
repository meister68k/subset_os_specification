# 極小UNIX `wc` 仕様書

| 項目 | 内容 |
|---|---|
| 文書ID | SUBSET-WC-001 |
| 版 | 0.1（初版仕様） |
| 対象 | サブセットOSの `/bin/wc` |
| 位置づけ | 入力の行数・単語数・byte数を数えるコマンド。pipeのread、EOF、集計出力を確認する |

## 1. 目的と適用範囲

入力データを逐次読み込み、行数・単語数・byte数を数えて標準出力へ表示する。引数なしで標準入力を使うため、`echo hello | wc`のようなpipelineでpipeのデータ転送とEOFを確認できる。

初版は入力元を標準入力またはpathnameに限定する。再帰処理、ディレクトリ、文字コード変換、ロケール依存の文字数計数、出力書式の幅指定は扱わない。文字数ではなくbyte数を数える。

内蔵バイナリ名は`"wc"`とし、`kernel::user_binary("wc")`から検索可能にする。`sh0`からはコマンド名`wc`で起動する。将来filesystem上のpathnameを導入する場合は`/bin/wc`とする。

## 2. 起動形式

```text
wc [-l] [-w] [-c] [file ...]
```

- `-l`は行数、`-w`は単語数、`-c`はbyte数を表示する。
- optionを一つも指定しない場合は、行数・単語数・byte数のすべてを表示する。
- 複数のcount optionを指定した場合は、指定された項目を`-l`、`-w`、`-c`の順に表示する。
- optionはpathnameより前に置く。`-lwc`のような連結optionは受け付けない。
- `--`は特別扱いしない。`-`は標準入力を表す。それ以外の先頭`-`は不明optionとして扱う。
- pathnameが省略された場合は標準入力fd=0を1回読み込む。
- pathnameが1つ以上ある場合は引数順に各入力元を処理する。pathname `-` は標準入力fd=0を表し、同一呼出し内で複数回指定した場合も同じfdの現在位置から読む。
- ファイル名のワイルドカード展開やクォート解釈は行わない（シェル側の責務）。

## 3. 集計規則

- **byte数**: `read()`で取得した入力byte数を数える。NUL、CR、LF、非ASCII byteもそれぞれ1 byteとして数える。
- **行数**: LF (`0x0A`) のbyte数を数える。LFで終わらない末尾のbyte列は追加の1行として数えない。
- **単語数**: 空白byte以外の連続列を1単語とする。空白判定はilibcの`std::isspace()`と同じ定義を使う。引数は`unsigned char`へ変換して渡す。CRも空白として扱う。
- 直前byteが空白で、現在byteが非空白なら単語開始として単語数を1増やす。
- 入力元ごとに単語状態を初期化する。複数pathnameの境界でbyte列を連結して一つの単語として扱わない。
- 集計はbyte単位で行い、UTF-8等の文字境界を解釈しない。

## 4. 出力形式

各入力元につき1行を標準出力fd=1へ出力する。

- 選択されたカウンタを10進表記し、ASCIIスペース1個で区切る。
- カウンタは`-l`、`-w`、`-c`の順に並べる。
- pathnameを指定した場合、カウンタの後にASCIIスペース1個とpathnameを出力する。標準入力を表す`-`の場合もpathnameとして`-`を表示する。
- 引数なしの場合、pathname欄は付けない。
- 各結果行の末尾にはLFを1 byte出力する。
- 初版では複数pathname指定時の総計行を出力しない。

例:

```text
$ echo hello | wc
1 1 6
$ wc -l -c file
2 14 file
```

## 5. 入力と集計処理

- 固定長buffer（推奨512 byte）を用い、`read(fd, buffer, sizeof(buffer))`を繰り返す。入力全体をメモリへ保持しない。
- 正のread結果について、返された範囲内の全byteを順に走査してカウンタを更新する。
- `read()`が0ならその入力元のEOFとする。正の短いreadはEOFとみなさず、次のreadを行う。
- `read()`が負値なら当該入力元の読み込みエラーとする。
- 選択されたカウンタは`uint32_t`で保持する。選択カウンタが`UINT32_MAX`に達した状態でさらに加算が必要になった場合はoverflowとして当該入力元の処理を失敗させる。wraparoundさせない。非選択カウンタのoverflowは判定しない。
- 標準入力fd=0は閉じない。コマンドがopenしたpathnameのfdは処理後にcloseする。

## 6. エラー処理・終了ステータス

| 状況 | 動作 |
|---|---|
| 引数形式またはoption不正 | 診断をfd=2へ出し、入力を開始せず`1`で終了 |
| pathnameの`open()`失敗 | 診断し、後続入力元を処理。最終statusを`1`にする |
| `read()`失敗またはカウンタoverflow | 当該入力元を失敗として打ち切り、可能ならその入力元の部分集計を出力して後続入力元を処理。最終statusを`1`にする |
| 結果出力の`write()`が0または負値 | 診断を試み、コマンド全体を中止して`1`で終了 |
| pathname fdの`close()`失敗 | 診断し、最終statusを`1`にする |
| 全入力元の処理と出力が成功 | `0`で終了 |

- 診断は標準エラーfd=2へ`wc:`を付けて出力する。診断自体の失敗で再試行を続けない。
- 部分writeは残りbyteを再送する。writeが0または負値なら無限再試行しない。
- 失敗が一つでもあれば、後続入力元を処理した場合も最終終了statusは`1`とする。

## 7. 使用API・実装制約

| 区分 | API | 用途 |
|---|---|---|
| OSラッパ | `open()`、`read()`、`close()` | pathname入力 |
| OSラッパ | `write()` | 標準出力と診断の出力 |
| ilibc | `std::isspace()`相当 | 単語区切り判定 |
| ランタイム | `main()`の戻り値 | Process終了status |

- `FILE*`、`printf()`、動的メモリ確保、ホストOS固有API、Filesystem内部APIは使わない。
- カウンタは固定幅整数で保持し、加算前に上限を検査する。10進出力変換も固定長領域内で行い、桁数上限を検査する。
- `std::isspace()`へ渡す値は`unsigned char`として扱い、負の`char`による未定義動作を避ける。

## 8. 受入テスト

1. 空入力を与え、3つのカウンタがすべて0となる。
2. `echo hello | wc`で、行数1・単語数1・byte数6を出力する。
3. 複数行、空行、LFで終わらない末尾データについて、行数がLF数と一致する。
4. 連続空白、先頭・末尾空白、タブ、CRを含む入力で単語数を確認する。
5. NULと非ASCIIを含む入力でbyte数を確認する。
6. `-l`、`-w`、`-c`それぞれと複数optionの出力順を確認する。
7. pathname入力、複数pathname、`-`による標準入力指定を確認する。
8. 部分read・部分writeを扱い、byteの重複や欠落がない。
9. open/read/write/close失敗とカウンタoverflowでstatus 1となり、標準入力をcloseしない。

## 9. 非対応機能

- `-L`による最長行byte数。
- optionの連結指定、`--`によるoption終端。
- pathname群の総計行。
- Unicode文字数・表示幅・ロケール依存の単語分類。
- 再帰的なdirectory走査。
