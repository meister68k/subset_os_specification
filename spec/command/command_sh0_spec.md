## 1. 目的と位置づけ

極小シェル`sh0`は、対話的に1行のコマンドを受け取り、組み込みコマンドを処理するか、外部プログラムを起動して終了を待つ最小のコマンドランチャーである。OSの`spawn` / `wait` / `chdir`、引数受渡し、標準入出力を検証することを主目的とする。

- シェルはユーザー空間プログラムであり、カーネルにコマンド構文解析を追加しない。
- 基本動作は **入力 → 分割 → 組み込み実行または外部プログラムの起動・待機 → 次の入力** の逐次実行とする。
- 動的メモリ確保なし。入力行と引数配列は固定長とする。
- cwd pathnameはシェル自身が固定長bufferに保持し、`pwd`はその値を表示する。OSの`getcwd` syscallには依存しない。
- ilibcの公開APIは増やさず、OS側のシステムコールラッパと既存ilibcを利用する。
- 初版で `exit` すればシェルは終了する。initから `wait` で起動されている場合、制御はinitへ戻る。

## 2. 起動形式と動作モード

実行ファイル名はファイルシステム上では `/bin/sh0` 、内部バイナリでは `sh0` とする。

```text
/bin/sh0
```

- **対話モードのみ**に対応する。標準入力 fd=0 から行入力し、標準出力 fd=1 にプロンプトを表示する。
- `sh0 /etc/rc` のようなスクリプトファイル指定、`sh0 -c ...`、シェルオプションは非対応。
- コマンドライン引数が1個以上ある場合は診断を出して終了コード1で終了する（暫定）。
- シェル自身の `stdin` / `stdout` / `stderr` は継承されたfd 0/1/2を用いる。端末専用APIには依存しない。

> **initとの関係**：`shell::wait:sh0` は使用可能。一方、`script::wait:/bin/sh /etc/rc` は次の段階でスクリプト機能を実装するまで非対応。

## 3. 入力構文

### 3.1 行入力

- 1物理行を1コマンドとする。
- 改行はLF (`\n`) を受け付け、引数に含めない。
- `std::isspace()`が真となる文字だけの行は何も実行せず次の入力へ進む。
- 先頭の空白類を除いた先頭文字が `#` の行はコメントとして読み飛ばす（暫定）。行末コメントは非対応。
- 入力バッファは128文字とし、最大入力行長は **126文字（LFを除く）** とする。LFと終端NULを含めて128文字に収める。127文字以上の本文は超過として扱い、行末LFまたはEOFまで読み捨て、1回だけエラーを報告して次の入力へ進む。
- CRLF専用の行末処理は行わない。行入力ではLFだけを行末として除くためCRは入力データに残るが、単語分割では`std::isspace()`に従って空白区切りとして扱う。
- EOFが行頭で発生したときはシェルを終了する。改行なしの最終行が残っている場合は、その行を1回処理してから終了する（暫定）。

### 3.2 単語の分割

- 単語区切りはilibcの`std::isspace()`が真となる文字とする。これは`"C"`ロケールのASCII空白類である。連続する区切りは1つとみなし、先頭・末尾の区切り文字は無視する。
- 引数は **最大8個** (`argv[0]` を含む)。超過した行は実行しない（暫定）。
- `argv[argc] = nullptr` を必ず付ける（9要素のポインタ配列）。
- `'` と `"` は通常文字。文字列の結合、引用符の除去を行わない。
- `\`、`$`、`*`、`?`、`;`、`|`、`<`、`>`、`&`、`(`、`)` はこの段階では**演算子として解釈しない**。単語の通常文字として外部コマンドに渡す。ワイルドカード・変数展開も行わない。
- 空白を含む1個の引数を指定する方法はない。

例：

```text
入力: echo "hello world"
argv[0] = "echo"
argv[1] = "\"hello"
argv[2] = "world\""
argv[3] = nullptr
```

## 4. コマンドの解決と実行

### 4.1 組み込みコマンド

`sh0`で提供する組み込みコマンドは`exit`、`cd`、`pwd`とする。

| 入力 | 動作 |
|---|---|
| `exit` | シェルを終了コード0で終了 |
| `exit` に引数がある | 引数不正を表示し、シェルは継続（暫定） |
| `cd path` | `chdir(path)` syscallを呼び、成功すればシェルProcessのcwdを変更 |
| `cd`（引数なし） | 使用方法を診断し、シェルは継続 |
| `cd` にpathが複数ある | 引数不正を診断し、`chdir()`を呼ばずシェルは継続 |
| `pwd` | 現在のcwdの絶対pathnameを標準出力へ1行出力 |
| `pwd` に引数がある | 引数不正を診断し、シェルは継続 |

`cd`と`pwd`は組み込みであり、子Processとしてspawnしてはならない。`export`、`set`、`echo`、`true`、`false`、`test`は組み込みとして実装しない。用意されたものは外部プログラムとして扱う。

#### `cd`の動作

- `cd`はpathnameをちょうど1つ受け取る。`HOME`環境変数や前回のdirectoryを保持する機能がないため、引数省略時の既定directoryや`cd -`による移動は提供しない。
- `cd path`は`btx::sys_chdir(path)`相当を1回呼び出す。directoryの存在確認、pathname解決、Process cwd参照の保持・交換は`chdir_implementation_spec.md`の責務とし、シェルが`stat()`やcwd inodeを直接操作しない。
- 絶対pathはrootから、相対pathは現在のシェルProcessのcwdから解決する。成功後のcwdは以降の相対path syscallで使われる。
- `sh0`は起動時にcwd文字列を`/`として初期化する（Process管理仕様上、initおよびspawnされたProcessの初期cwdはrootまたは親Processのcwd）。
- `chdir()`を呼ぶ前に、cwd文字列とpathから移動後の絶対pathname候補を固定長buffer内で構成する。絶対pathはrootから、相対pathは保持中cwdから組み立て、空componentと`.`を除去し、`..`で直前componentへ戻す（rootより上には移動しない）。連続slashは1つとして扱う。候補がbufferに収まらない場合は診断し、`chdir()`を呼ばずcwd文字列も変更しない。
- `chdir()`が`0`を返した場合に限り、候補pathnameをシェル内cwd文字列へ反映する。失敗時は文字列を更新しない。
- 成功時は出力しない。失敗時はfd=2へ`sh:`を付けて診断し、次のプロンプトへ進む。失敗時のcwd状態は`chdir()` syscall仕様に従う（通常の検証失敗では不変だが、旧cwd参照release後の失敗では新cwdへ遷移済みの場合がある）。
- `-`を含むpathも通常のpathnameとして渡し、optionや「前回directory」として解釈しない。空白区切りのみの構文のため、空白を含むpathnameは指定できない。
- `spawn()`で起動される子Processは、Process管理仕様に従い`cd`後のcwdを継承する。

#### `pwd`の動作

- `pwd`は引数を取らない。引数が指定された場合はfd=2へ`sh:`を付けて使用方法を診断し、cwd記憶bufferの表示を行わず次のプロンプトへ進む。
- `pwd`はcwd記憶bufferに保持した絶対pathnameとLFを標準出力へ出力する。root cwdは`/`と表示する。
- cwd記憶bufferは128 byteとし、終端NULを含める。pathname本文は最大127 byteとする。`pwd`はProcess cwdを変更せず、cwd取得syscallも呼ばない。
- 標準出力への書き込みに失敗した場合はfd=2へ診断し、シェルを継続する。
- 表示する値はsh0が認識している論理pathnameである。外部Processがcwd directoryを`rmdir()`した場合や、`chdir()`がcwd更新後の後処理失敗で`-1`を返した場合、保持pathnameと実際のProcess cwdが一致しなくなる可能性がある。この方式ではそれらを再取得・検出できない。

### 4.2 実行ファイルの探索

環境変数 `PATH` は使用しない。実行対象の解決は実装段階で次のように扱う。

1. **現段階**：`spawn`は内蔵バイナリ名だけを起動できる。内蔵バイナリ名に`/`は含まれない。コマンド名をそのまま内蔵バイナリ名として渡し、該当しなければ起動失敗として扱う。`/bin/cat`等のパス起動はまだ提供しない。
2. **将来段階**：`spawn`はフルパスで実行ファイル名を受け取る仕様とする。内蔵バイナリ名とフルパスの対応・解決方法は未確定であり、ここでは定めない。`PATH`検索は行わない。
3. いずれの段階でも、受け渡しに必要な固定長バッファに収まらない場合はエラーとし、途中で切り詰めない。

| 入力 | 実行パス |
|---|---|
| `echo hello` | `echo` |
| `/bin/cat /etc/inittab` | 将来段階で`/bin/cat` |
| `./test` | 将来段階で`./test` |
| `tools/test` | 将来段階で`tools/test` |

`argv[0]`は入力されたコマンド名を維持する。現段階の内蔵バイナリ名解決ではこの値を`spawn`の名前引数にも用いる。将来段階でフルパス引数を別に渡す場合も、プログラムへ渡す`argv[0]`は入力されたコマンド名とする。

外部プログラムから行う相対pathname操作は、シェルが保持するcwdを子Processが継承することで`cd`後のdirectoryを基準にする。現段階の内蔵バイナリ名検索自体はcwdによる`PATH`検索を行わない。

### 4.3 実行・待機

1. 1行を解析し、外部コマンドの `argv[]` を作る。
2. 現段階では`spawn(argv[0], argv)`相当を呼び、内蔵バイナリ名として解決する。将来段階ではフルパスを`spawn`へ渡す。パス引数と`argv[0]`の対応はOS側のspawn仕様で確定する。
3. 起動に成功した場合、その子プロセスの終了を `wait()` 相当で待つ。
4. 終了後、次のプロンプトを表示する。

同時起動数は1。バックグラウンド実行やジョブ制御はない。子プロセスへは標準fd 0/1/2を継承させる想定とする。

## 5. プロンプト・表示

- プロンプトは **`$ `** とし、標準出力fd=1に出力する（暫定）。
- 改行は付けず、入力を受け付ける前に出力を完了する。
- コマンドの通常出力は子プロセスが直接標準出力へ行う。シェルは出力を捕捉・加工しない。
- シェルからの診断は標準エラーfd=2に表示し、`sh: ...` を付ける。
- 行編集、履歴、補完、カーソル制御、端末エコーの制御は行わない。入力のエコーは端末・コンソールドライバ側の責任とする。

使用例：

```console
$ echo Hello, World
Hello, World
$ cat /etc/inittab
boot::wait:/bin/echo Starting
shell::wait:/bin/sh
$ cd /tmp
$ cat notes.txt
$ exit
```

## 6. エラー処理・終了ステータス

Level 0では、**コマンド単位の失敗でシェルを終了しない**ことを基本原則とする。次の表は初版の推奨規則（暫定）。

| 事象 | 動作 |
|---|---|
| 空行・コメント | 無視して次のプロンプト |
| 入力行長超過 | 残りを読み捨てて診断、次のプロンプト |
| 引数8個超過 | 診断して実行せず、次のプロンプト |
| 実行パスが長すぎる | 診断して実行せず、次のプロンプト |
| `spawn`失敗（存在しないコマンドなど） | 診断して次のプロンプト |
| 子が非0終了 | 子の終了コードをシェル全体のエラーとはみなさず、次のプロンプト |
| `wait`失敗 | 診断し、同じ子を再度`wait`する。回収に成功するまで次のプロンプトへ進まない |
| `cd`の引数なし・複数path | 診断し、`chdir()`を呼ばず次のプロンプトへ |
| `chdir()`失敗 | 診断して次のプロンプトへ。cwd状態はsyscall契約に従う |
| `exit` | 正常終了（0） |
| 入力先頭でEOF | 正常終了（0） |
| 行入力中のI/Oエラー | 診断してシェル異常終了（1） |
| プロンプトの書き込み失敗 | シェル異常終了（1） |
| 起動引数が不正 | 診断してシェル異常終了（1） |

全体の終了コードは `0`（`exit`またはEOFによる正常終了）と `1`（シェル自身の致命的エラー）とする（暫定）。直前の子の終了コードを `exit` の戻り値として採用する機能や `$?` は次ステップ以降の検討対象。

## 7. 入力バッファと資源上限

| 資源 | 初版案 |
|---|---|
| 入力行本文 | 最大126文字（LFを除く） |
| 入力バッファ | 128文字（本文126文字、LF、終端NUL） |
| 引数数 | 最大8個 |
| `argv` 配列 | 9要素（終端nullptrを含む） |
| 実行パス用バッファ | 少なくとも 最大入力単語 + 終端NUL を収容できる容量。具体値は実装時固定 |
| 動的メモリ確保 | なし |
| 同時起動する外部コマンド | 1個 |

注意：ilibcの `gets()` はサイズ到達で行の残りを次回に持ち越す。**行長を確定する前に解析・実行してはならない**。126文字ちょうど、127文字以上、LF、CRLF（CRは行バッファに残るが`isspace()`で区切られる）、改行なしEOF、長すぎる行の残部読み捨てをテストする。`gets`は入力バイト数を返さないため、埋め込みNULの厳密検出は保証しない（init仕様と同様、テキスト入力を前提とする）。

## 8. ilibcおよびOSとの境界

### 8.1 使用する既存ilibc機能

| API | 用途 |
|---|---|
| `ilibc::gets(line, 0, ilibc::clear_errno(err))` | 1行入力とI/Oエラー判定 |
| `std::strlen()` | 文字列長・パス長判定 |
| `std::memcpy()` | 必要に応じて固定長パスバッファを構築 |
| `std::isspace()` | 入力行の空白類判定・単語分割 |
| `ilibc::putstr()` またはOSの `write()` | プロンプトの出力 |
| `ilibc::fprint_f<fmt>()` | 診断。`%s`・`%d`で足りる |

単語分割は入力バッファ中にNULを置く、状態を持たない小さな専用関数をシェル内部に実装する。`strtok`や`malloc`を新設しない。

### 8.2 OS側への依存

- プロンプトと診断：OSの標準fd 1/2への書き込み。
- 外部コマンド起動・終了待ち：`spawn`、`wait`相当。
- `cd`：`btx::sys_chdir(path)`相当の`chdir` syscall。
- `pwd`：シェル内cwd記憶bufferのみを使用し、OS syscallを追加しない。
- シェルの終了：`main()`のreturnからランタイムが終了システムコールを呼ぶ。
- OS専用の入力バックエンドが必要。ILIBC-REF-001 v0.1では、`<cstdio>` のPOSIX用バックエンドが定義され、実機向けCUSTOMバックエンドは未実装という記述である。

## 9. 非対応機能（次ステップ以降）

- ファイルからのシェルスクリプト実行（`sh /etc/rc`）、`-c`。
- リダイレクト `<`、`>`、`>>`、パイプ `|`、バックグラウンド `&`。
- 複数コマンドを1行に書く `;`、論理演算 `&&` / `||`。
- クォート、エスケープ、環境変数、PATH探索、ワイルドカード展開。
- `if`、`for`、`while`、関数、コマンド置換。
- `export`、ジョブ制御、シグナル処理、履歴、補完、行編集。

## 10. 最小受入テスト

| 入力・状況 | 期待結果 |
|---|---|
| 空行・空白行 | 起動なし、次のプロンプト |
| `echo hello` | `echo`起動、`hello`を渡して終了待ち |
| `/bin/echo hello` | 現段階では内蔵バイナリ名として解決できず起動失敗。将来は指定フルパスで起動 |
| `echo "a b"` | 3単語に分割。引用符を保持 |
| `echo a;b` | `a;b`を単なる引数として渡す |
| `unknowncmd` | 起動失敗を表示して継続 |
| `cd /tmp` | `chdir()`を呼び、成功後の相対path操作にcwdが反映される |
| `cd`、`cd a b` | 診断し、`chdir()`を呼ばず継続 |
| 通常fileや不存在pathへの`cd` | 失敗を診断し、shellを継続 |
| `cd`成功後に外部コマンドを起動 | 子Processが更新後のcwdを継承 |
| `pwd`をroot cwdで実行 | `/`とLFを出力し、cwd不変 |
| `cd /tmp`成功後に`pwd` | `/tmp`とLFを出力 |
| 相対`cd`のpathに`.`、`..`、連続slashを含む | syscall成功後、正規化した絶対pathnameを`pwd`で出力 |
| cwd pathname候補がbuffer容量を超える`cd` | `chdir()`を呼ばず診断し、cwd文字列不変 |
| `pwd extra` | 診断し、cwdを変更せず継続 |
| `pwd`出力失敗 | 診断して継続し、Process cwd不変 |
| 9引数のコマンド | 起動せずエラー、継続 |
| 126文字ちょうどの本文とLF | 有効な行として処理可能 |
| 127文字以上の本文 | 行全体を破棄して継続 |
| CRLF | CRを行バッファに残し、`isspace()`による単語分割で空白として扱う |
| `exit` | シェルが0で終了 |
| 入力先頭でEOF | シェルが0で終了 |
| 読み込みエラー | シェルが1で終了 |

## 11. 正式実装前に確定する事項

1. 入力最大126文字、最大8引数、プロンプト`$ `の採否。
2. `exit`の引数と終了コード、EOF直前の不完全行の処理。
3. エラー時の継続・終了規則、入力のコメント行取り扱い。
4. 内蔵バイナリ名と将来のフルパスの対応・解決方法。OS側の段階別spawn仕様と整合させる。
5. sh0内のcwd記憶と`chdir()`の後処理失敗、cwd directory削除時に表示値が実cwdとずれる制限を、次段階でどのように扱うか。
