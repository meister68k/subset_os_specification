# 極小UNIX `ls` 仕様書

| 項目 | 内容 |
|---|---|
| 文書ID | SUBSET-LS-001 |
| 版 | 0.1（実装前ドラフト） |
| 対象 | サブセットOSの `/bin/ls` |
| 位置づけ | UNIX V7に着想を得た、単純なディレクトリ列挙コマンド |
| 依拠する仕様 | `filesystem_external-api_spec.md`（raw dirent）、`filesystem_design_spec.md`、`stat_implementation_spec.md`、ilibc APIリファレンス |

## 1. 目的と範囲

指定したディレクトリ内の名前、または指定した通常ファイル自身の名前を標準出力へ列挙する。初版では表示を**常に1エントリ1行**とし、端末幅に応じた多段組、ソート、詳細情報表示などは行わない。ディレクトリの生バイト読み込みと`stat()`を検証できることを重視する。

本書はユーザランドコマンドの仕様であり、OS・ファイルシステム側の公開APIの新設は要求しない。ただしディレクトリに対する`open/read`と`stat`のユーザ向けシステムコール経路が使用可能であることが前提となる。

## 2. 起動形式とオプション

```text
ls [-a] [path ...]
```

- 引数なしならカレントディレクトリ `.` を表示する。
- `path` はファイルまたはディレクトリを指定できる。絶対パス、相対パスを許容する。
- `-a` を指定すると、名前が `.` で始まるエントリも表示する。指定がなければ隠しエントリを省略する。
- 初版では `-a` のみを認識する。オプションをまとめた `-al`、`-la` 等は未対応（不明なオプションとしてエラー）。
- `--`、`--help`、`--version` は非対応。`-` で始まるパスをオプションと区別する方法は初版では規定せず、制約として記載する（例：`./-name` はパスとして指定可能）。
- `-l`（詳細表示）、`-R`（再帰）、`-d`、`-i`、`-t`、`-r` 等は初版では非対応。
- オプションはパス引数の前にのみ許容する。最初のパス引数以後は、後続をすべてパスとして解釈する。
- ワイルドカード、クォート、環境変数は展開しない。シェルが生成した `argv` をそのまま利用する。

## 3. 出力形式・表示順序

- エントリ名をASCII/バイト列として出力し、直後にLF (`\n`) を1つ付加する。
- 表示順序は**ディレクトリ内部の記録順（物理dirent順）**とし、辞書順ソートを行わない。
- 表示に列幅調整、色、種類を表す接尾辞、権限やサイズの付記はしない。
- `inode_num == 0` の空きスロットは表示しない。
- `-a` なしの場合、`name[0] == '.'` のエントリは表示しない。`-a` ありなら `.` および `..` もディレクトリに実在する場合に限り表示する。仮想的には生成しない。
- ファイルを直接指定した場合は、そのパスを1行で表示する。ファイル名だけに縮めない（例：`ls /tmp/a` → `/tmp/a\n`）。この直接指定には隠し名除外規則を適用しない。
- 単一ディレクトリの内容では、ディレクトリ自身の名前や見出しを表示しない。
- 複数の`path`を指定したときは引数順に処理し、**各ディレクトリの先頭に `path:` の見出し**を付ける。対象間は空行1行で区切る。通常ファイルは自身の指定パス1行のみを表示する。順序のグルーピングや並べ替えは行わない。
- 文字コード変換・特殊文字エスケープは行わない。ファイル名はOSが保証するNUL終端の名前を使う。

### 3.1 動作例（記録順は例示）

```text
$ ls
bin
etc
readme
$ ls -a
.
..
bin
etc
.hidden
readme
$ ls /etc/inittab
/etc/inittab
$ ls -l
ls: unsupported option: -l
```

## 4. ディレクトリ取得方法：V7方式のraw dirent

既存FS仕様は、ディレクトリも `open()` / `read()` でき、**シリアライズ済みdirentを32バイト単位で読む**形式である。専用の`readdir()`、`getdents()`は不要。

| 項目 | 値・契約 |
|---|---|
| `DIRENT_SIZE` | 32バイト |
| inode番号 | 先頭4バイト、リトルエンディアン `uint32_t` |
| 名前フィールド | 続く28バイト。最大27バイト＋NUL |
| 空きエントリ | inode番号が0 |
| 読み出し単位 | `read(fd, raw, 32)` |
| 実行環境 | Cortex-M0 / MC68000 共通でオンディスク表現はLE固定 |

- 生データを `struct dirent*` へ**直接キャストしない**。明示的なLE decodeを行う。
- カーネル内部の `fs::dirent_decode()` をユーザランドからリンク・直接参照する必要はない。共通の**公開フォーマット定数・デコード補助関数**をユーザ側に提供するか、`ls`専用の数行のdecode実装を設ける。これはlibc API追加を意味しない。
- 名前の終端NULは最大28バイトの範囲内で検査する。見つからなければ破損したdirentとして扱う。
- 空きスロットはinode番号のみで判定し、名前が空文字かどうかで判定しない。
- `read()==0` を正常EOFとする。32バイト未満の正の値は、通常の短いreadの可能性を考慮して不足分を読み足し、32バイトに満たないままEOFとなったときは不正なディレクトリ長としてエラーにする。
- `read()<0` はI/Oエラーとして扱う。バッファ境界を越える読み込みや同期化のためのseekは行わない。
- **前提条件:** OS側がディレクトリに対する`read(fd, ..., 32)`を許容し、連続呼出しでオフセットを進めること。カーネル側でディレクトリ読み取りを拒否する実装になっている場合は、既存FS仕様との接続が必要。

## 5. 対象パスの判定

1. 処理対象の`path`へ `stat(path, &st)` を行う。
2. `S_ISDIR(st.st_mode)` ならディレクトリとして `open(path, O_RDONLY, ...)`、続いてraw direntを列挙する。
3. ディレクトリ以外のファイルは、指定された`path`文字列を1行だけ出力する（このため開く必要はない）。
4. `stat()` が失敗した場合、診断を出してその対象をスキップする。
5. ディレクトリ列挙中に個々のエントリに対して`stat()`は行わない（基本表示に必要ないため）。

`S_ISDIR`および`struct stat`はOS側の`<sys/stat.h>`（UNIX互換の公開ABI）を用いる。`open()`はOS仕様の実際の3引数形式 `open(path, flags, mode)` に合わせる。読取専用では第3引数は0とする。

## 6. エラー処理・終了ステータス

| 状況 | 動作 |
|---|---|
| 不明なオプション | fd=2へ診断し、列挙開始前に終了ステータス1 |
| `stat()` 失敗 | エラー表示、そのパスをスキップし次へ |
| `open()` 失敗 | エラー表示、そのディレクトリをスキップし次へ |
| `read()` 失敗 | 当該ディレクトリの列挙を中止し次のパスへ |
| 途中EOFによる不完全dirent・名前終端の欠如 | 破損として診断し、当該ディレクトリの列挙を中止 |
| `close()` 失敗 | 診断表示し失敗を記録、次へ |
| stdoutの `write()` が0または負値 | 診断し、コマンド全体を中断 |
| stdoutへの正の部分書き込み | 未送信分を繰り返し書く |
| エラーが一件もない | 終了ステータス0 |
| 何らかのエラーがあった | 終了ステータス1 |

- 診断はfd=2へ出力し、行頭には`ls:`を付ける。正確なエラー文言・errno数字の表示は実装依存。
- 診断自体が失敗しても再帰的にエラー処理しない。
- `ls`が開いたディレクトリFDは、エラー時を含め必ず閉じる。fd=0/1/2は閉じない。
- 複数パスの中でエラーが起きても、書き込み失敗以外は後続のパスを処理する。

## 7. 利用API・実装制約

| 区分 | API | 用途 |
|---|---|---|
| OSラッパ | `stat()` | パスの種類を判定 |
| OSラッパ | `open()`、`read()`、`close()` | ディレクトリ読み込み |
| OSラッパ | `write()` | stdoutと診断出力 |
| ilibc | `std::strlen()` | 名前・パスの文字列長 |
| ilibc（任意） | `std::strcmp()` | オプション判定 |
| ローカル処理 | LE32 decode・名前NUL検証 | direntの解釈 |

- `FILE*`、`malloc/free`、`printf()`、浮動小数点、RTTI、例外を使用しない。
- バッファは32バイトのdirentと小規模な表示用領域で十分。ディレクトリ全件をメモリに蓄積しない。
- `stat` とraw direntの公開ヘッダ定義は、OS本体のABIとの一致を優先する。ホストPOSIXで同じバイナリをそのまま動作させることは想定しない。
- 生direntを扱う方式はFSオンディスク形式への依存を作る。後日VFSを拡張した場合には列挙APIの抽象化が必要になる可能性がある。

## 8. 受入テスト

1. 引数なしでカレントディレクトリの非隠しエントリを1行ずつ表示する。
2. `-a`指定で隠しエントリを表示する。存在する `.` / `..` を表示し、存在しない場合は生成しない。
3. 列挙順が実ディレクトリの記録順であることを確認する。
4. 空きslot（inode=0）を表示しない。
5. 単独の通常ファイル指定では指定パスそのものを表示する。
6. 複数の対象を引数順に処理し、ディレクトリには見出しを付ける。
7. `stat/open/read` 失敗時に診断し、後続の対象を処理する。
8. 32バイトdirentが複数の短いreadに分割されても欠落なく復元する。
9. 不完全dirent・NUL欠落・LE inode番号の復元を検証する。特にMC68000では構造体キャストをしないことを確認する。
10. stdoutの部分writeを再送し、write失敗時に停止する。
11. 開いたFDを必ず閉じ、既存の標準FDを閉じない。
12. 存在しないパスを混在させた場合、列挙可能な後続パスは表示し、戻り値1とする。

## 9. 未確定・拡張候補

1. **初版オプション:** 本案では `-a` のみ採用し、`-l`やソートは採用しない。利用者合意前の提案である。
2. **複数パスの表示:** 見出し、空行区切りの細則は本案で提案したもので、変更可能。
3. **ディレクトリraw形式の公開:** on-disk 32バイト形式をユーザランドに公開するため、公開ヘッダの置き場所・名称とABIテストを実装段階で確定する。
4. **将来の `ls -l`:** `stat()`の`st_mode`、`st_size`、`st_nlink`、`st_mtime`などを利用可能。ただし日時文字列化や権限表記の実装量が増えるので別段階とする。
5. **表示順:** ソートを省くため、出力順序はFSの内部配置に依存する。これは初版の意図的な簡略化である。
