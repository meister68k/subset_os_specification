# ed サブセット実装仕様書

## 1. 概要

### 1.1 目的

本仕様書は、UNIX系ラインエディタ `ed` のサブセット実装について、機能、コマンド構文、データ構造、エラー処理およびファイル入出力の仕様を定義する。

本プログラムは、UNIX風サブセットOS上で動作する、単一ファイル専用のラインエディタである。

### 1.2 設計方針

以下の方針に従う。

- 実装規模を小さく保つ。
- 固定長配列を使用し、動的メモリ確保を避ける。
- 正規表現および検索機能を実装しない。
- 編集対象のファイルは起動時に指定する。
- 編集対象の変更や複数ファイルの同時編集をサポートしない。
- 端末の画面制御機能を使用しない。
- エラーメッセージを短く統一する。
- コマンドの動作とエラー条件を明確に定義する。

### 1.3 用語

| 用語 | 定義 |
|---|---|
| 行 | LFを区切りとするテキストの単位 |
| 行バッファ | 編集対象の全行を保持するメモリ領域 |
| 現在行 | コマンドの既定の操作対象となる行 |
| アドレス | 編集対象の行を指定する値 |
| 範囲 | 開始行と終了行で指定される連続した行の集合 |
| 未保存状態 | バッファの内容が最後の正常な保存結果と異なる状態 |
| コマンドモード | コマンドを入力する状態 |
| テキスト入力モード | 行の追加・挿入・置換のためにテキストを入力する状態 |

## 2. 起動仕様

### 2.1 コマンドライン

起動形式は以下とする。

    ed filename

`filename` は編集対象のファイル名である。

引数は1個だけ受け付ける。

| 条件 | 動作 |
|---|---|
| 引数が1個 | ファイルの読み込み処理を開始する |
| 引数が0個 | `No file` を表示して異常終了する |
| 引数が2個以上 | `Bad cmd` を表示して異常終了する |

ファイル名の解釈はOSのファイルシステムに従う。

### 2.2 既存ファイル

指定したファイルが存在する場合、ファイル全体を行バッファに読み込む。

読み込みに成功した場合、読み込んだ内容を初期状態とする。

- 現在行は最終行とする。
- 未保存状態は解除する。
- ファイル名を以後の保存先として保持する。

空ファイルの場合、行数は0、現在行は0とする。

### 2.3 新規ファイル

指定したファイルが存在しない場合、新規ファイルとして編集を開始する。

- 行バッファを空にする。
- 現在行を0とする。
- 未保存状態を解除する。
- ファイル名を保存先として保持する。

新規ファイルの作成は、最初の `w` コマンドが実行されたときに行う。

ただし、ファイルが存在しないことを確認できた場合に限り、新規ファイルとして扱う。権限不足など、その他の理由で読み込みに失敗した場合はエラー終了する。

### 2.4 起動時の読み込み制限

読み込み対象が最大行数または最大行長の制限を超える場合、エラー終了する。

この場合、部分的に読み込んだ内容を編集対象として公開しない。

起動時の読み込みに失敗した場合、ファイルの内容を変更してはならない。

## 3. リソース制限

### 3.1 行バッファ

初期実装では、以下の固定上限を採用する。

| 項目 | 値 |
|---|---:|
| 最大行数 | 256行 |
| 最大行長 | 128バイト |
| 行末 | LF |
| 文字列終端 | NUL |

最大行長128バイトには、終端のNUL文字を含めない。

行バッファは最大256行を保持できるものとする。

各行は独立した文字列として管理する。

### 3.2 文字コード

本仕様では、文字コードを特定のマルチバイト文字コードに限定しない。

ただし、行長の上限はバイト単位で判定する。

UTF-8などのマルチバイト文字を含む行では、文字数とバイト数が一致しない場合がある。

NUL文字を含むバイナリデータはサポート対象外とする。

### 3.3 行の終端

入力されたテキスト行の末尾にある改行文字は、行データに含めない。

ファイル読み込み時にはLFを行区切りとして扱う。

CRLF形式のファイルを読み込む場合は、CRLFを1つの行区切りとして扱い、CRを行データに残さない。

保存時には、各行の末尾にLFを付加する。

したがって、CRLF形式で読み込んだファイルを保存すると、LF形式に変換される。

### 3.4 容量超過

行数または行長が上限を超える場合、対象の追加・挿入を拒否する。

- 行長超過では、入力行を切り詰めない。
- 行数超過では、上限を超える行を追加しない。
- 容量超過によって配列の範囲外にアクセスしてはならない。

## 4. データ管理

### 4.1 行バッファ

行バッファは、行データの配列と管理情報から構成する。

概念上、以下の情報を保持する。

| メンバ | 意味 |
|---|---|
| `lines` | 各行の文字列 |
| `line_count` | 現在の行数 |
| `current_line` | 現在行の行番号 |

実際の型名やクラス構成は実装時に決定する。

### 4.2 行番号

行番号は1始まりとする。

有効な行番号は次の範囲とする。

    1 <= line_number <= line_count

空のバッファでは、有効な行番号は存在しない。

現在行は以下の条件を満たすものとする。

- 行数が0の場合、現在行は0。
- 行数が1以上の場合、現在行は1以上、行数以下。

### 4.3 現在行の更新

各コマンドの実行後、現在行を以下の規則で更新する。

| コマンド | 実行後の現在行 |
|---|---|
| `a` | 最後に追加した行 |
| `i` | 最後に挿入した行 |
| `c` | 置換後の最後の行 |
| `d` | 削除位置の後続行。存在しなければ新しい最終行 |
| `p` | 表示範囲の最終行 |
| `n` | 表示範囲の最終行 |
| `=` | 変更しない |
| `w` | 変更しない |
| `q` | プロセス終了 |
| `Q` | プロセス終了 |

`c` によって対象範囲が削除され、新しい行が追加されなかった場合は、削除後の位置に後続行があればその行、なければ新しい最終行を現在行とする。

編集の結果、バッファが空になった場合は現在行を0とする。

### 4.4 未保存状態

バッファの変更状態を管理する。

未保存状態は、起動時の読み込み完了後には解除されているものとする。

実際にバッファの内容が変更された場合、未保存状態を設定する。

表示など、バッファの内容を変更しない操作では状態を変更しない。

正常な `w` コマンドの完了時には未保存状態を解除する。

書き込みに失敗した場合は、未保存状態を維持する。

---

## 5. コマンド構文

### 5.1 一般構文

コマンドの基本構文は以下とする。

    [address][command]

または

    [address1],[address2][command]

`address` は単一アドレス、`address1,address2` は範囲指定である。

アドレスとコマンドの間に空白を必要としない。

例：

    1p
    3d
    1,5n
    .,$p

コマンドごとのアドレス指定の可否と省略時の動作は、第7章で定義する。

### 5.2 コマンド行

コマンドは1行単位で入力する。

空行が入力された場合は、何もせず次のコマンド入力へ進む。

不正なコマンドはエラーとし、回復可能な場合はコマンド入力を継続する。

### 5.3 未対応構文

本仕様で定義されていないコマンド、アドレス表現、コマンド引数は受け付けない。

特に以下はサポートしない。

- 相対アドレス
- 正規表現
- 検索
- 複数コマンドの連結
- コマンドの省略形
- マーク
- 外部コマンド実行

---

## 6. アドレス仕様

### 6.1 単一アドレス

以下のアドレスをサポートする。

| アドレス | 意味 |
|---|---|
| 数値 | 指定された行番号 |
| `.` | 現在行 |
| `$` | 最終行 |

数値は10進整数として解釈する。

### 6.2 範囲指定

2つのアドレスをカンマで区切り、連続した行範囲を指定する。

例：

    1,5p
    .,$n

開始行と終了行を含む範囲とする。

以下を満たす必要がある。

    1 <= start_line
    start_line <= end_line
    end_line <= line_count

条件を満たさない場合はエラーとする。

### 6.3 アドレス省略

アドレスを省略した場合の動作はコマンドごとに定義する。

| コマンド | 省略時の対象 |
|---|---|
| `a` | 現在行の後 |
| `i` | 現在行の前 |
| `c` | 現在行 |
| `d` | 現在行 |
| `p` | 現在行 |
| `n` | 現在行 |
| `=` | 最終行番号 |
| `w` | バッファ全体 |
| `q` | アドレス不要 |
| `Q` | アドレス不要 |

空のバッファにおいては、`a` のみアドレスを省略して実行できる。

この場合、最初の行としてテキストを追加する。

空のバッファにおける `i`、`c`、`d`、`p`、`n` はエラーとする。

### 6.4 不正なアドレス

以下はエラーとする。

- 行番号が数値として正しく解釈できない。
- 行番号が有効範囲外である。
- 範囲の開始行が終了行より大きい。
- アドレスの構文が不正である。
- コマンドが許可していない形式のアドレスを指定している。

## 7. 編集コマンド

### 7.1 `a`：追加

指定行の後にテキストを追加する。

構文：

    [address]a

アドレスを省略した場合は現在行の後に追加する。

空のバッファでは、最初の行を追加する。

実行するとテキスト入力モードに移行する。

入力された各行を、指定位置の後に順番に追加する。

入力終了後は、最後に追加した行を現在行とする。

入力を1行も行わなかった場合、バッファは変更されない。

### 7.2 `i`：挿入

指定行の前にテキストを挿入する。

構文：

    [address]i

アドレスを省略した場合は現在行の前に挿入する。

実行するとテキスト入力モードに移行する。

入力終了後は、最後に挿入した行を現在行とする。

空のバッファでは使用できない。

### 7.3 `c`：置換

指定した行または範囲を削除し、その位置に新しいテキストを挿入する。

構文：

    [address]c
    [address1],[address2]c

実行するとテキスト入力モードに移行する。

指定範囲を削除した後、新しい行を入力する。

入力終了後は、置換後の最後の行を現在行とする。

入力が0行の場合は、指定範囲を削除する操作として扱う。

### 7.4 `d`：削除

指定した行または範囲を削除する。

構文：

    [address]d
    [address1],[address2]d

指定範囲の行を削除し、残りの行を詰める。

削除後の現在行は、第4.3節の規則に従う。

実際に行が削除された場合、未保存状態を設定する。

### 7.5 `p`：表示

指定した行または範囲を表示する。

構文：

    [address]p
    [address1],[address2]p

各行を1行ずつ標準出力へ出力する。

行番号は表示しない。

表示後は、表示範囲の最終行を現在行とする。

### 7.6 `n`：行番号付き表示

指定した行または範囲を行番号付きで表示する。

構文：

    [address]n
    [address1],[address2]n

各行を以下の形式で表示する。

    line_number text

行番号と本文の間にはスペースを1個置く。

行番号は10進数とする。

表示後は、表示範囲の最終行を現在行とする。

### 7.7 `=`：行番号表示

指定したアドレスの行番号を表示する。

構文：

    [address]=

アドレスを省略した場合は最終行番号を表示する。

出力は行番号のみとする。

現在行および未保存状態は変更しない。

空のバッファでは、最終行番号として0を表示する。

## 8. テキスト入力モード

### 8.1 モード移行

以下のコマンドはテキスト入力モードへ移行する。

- `a`
- `i`
- `c`

その他のコマンドはテキスト入力モードへ移行しない。

### 8.2 入力終了

テキスト入力モードでは、`.` だけの行が入力された場合に入力を終了する。

入力終了後はコマンドモードに復帰する。

`.` だけの行を通常の本文として入力するエスケープ機能は実装しない。

### 8.3 入力行の処理

各入力行について、以下を確認する。

1. 最大行長を超えていないこと。
2. 行バッファの最大行数を超えていないこと。
3. 行データがNUL終端されていること。

条件を満たさない行は追加しない。

エラー表示後も、テキスト入力モードを継続し、`.` によって入力を終了できるものとする。

---

## 9. ファイル保存

### 9.1 `w`：保存

構文：

    w

`w` は、起動時に指定したファイルへ行バッファ全体を書き出す。

ファイル名の引数は受け付けない。

以下の仕様に従う。

- ファイルを新規作成する場合は、通常のファイル作成APIを利用する。
- 既存ファイルの場合は、内容を上書きする。
- 各行の末尾にLFを付加する。
- 空のバッファを保存した場合は、空ファイルとする。
- 保存が正常に完了した場合、未保存状態を解除する。
- 保存に失敗した場合、未保存状態を維持する。
- 保存後も現在行を変更しない。

### 9.2 書き込み処理

書き込み処理では、部分書き込みを考慮する。

書き込みAPIが要求した長さより少ないバイト数を書き込んだ場合、残りのデータを書き込む。

書き込みエラーが発生した場合は保存失敗とする。

保存失敗時にはエラーメッセージを出力し、コマンド入力へ戻る。

### 9.3 保存方式の制約

初期実装では、既存ファイルへの直接上書きを許可する。

一時ファイルを経由した原子的な置換保存は必須としない。

そのため、書き込み途中のエラーによって既存ファイルの内容が不完全になる可能性がある。

この制約は実装上の既知の制限とする。

---

## 10. 終了コマンド

### 10.1 `q`：通常終了

構文：

    q

未保存状態に応じて動作する。

| 状態 | 動作 |
|---|---|
| 未保存状態ではない | 正常終了 |
| 未保存状態である | `No save` を表示し、終了を拒否 |

終了を拒否した場合、コマンド入力を継続する。

### 10.2 `Q`：強制終了

構文：

    Q

未保存状態の有無にかかわらず、エディタを終了する。

未保存の変更は保存しない。

終了前の確認入力は要求しない。

`Q` は大文字と小文字を区別し、小文字の `q` と異なるコマンドとして扱う。

---

## 11. エラー処理

### 11.1 エラーメッセージの形式

エラーメッセージは英語のASCII文字列とし、8文字以内とする。

エラー発生時には、メッセージを標準エラー出力へ1行出力する。

回復可能なエラーでは、エディタを終了せず、コマンド入力を継続する。

### 11.2 エラーメッセージ一覧

| エラー条件 | メッセージ |
|---|---|
| 不正なコマンド | `Bad cmd` |
| 不正なアドレス | `Bad addr` |
| 不正な範囲指定 | `RangeErr` |
| 空バッファへの不正な操作 | `No lines` |
| 最大行数超過 | `Too many` |
| 最大行長超過 | `Long line` |
| ファイル読み込みエラー | `Read err` |
| ファイル書き込みエラー | `WriteErr` |
| 未保存状態での `q` | `No save` |
| ファイル指定なしで起動 | `No file` |
| ファイルを開けない | `Open err` |
| 不正なコマンド構文 | `Syntax` |

すべて8文字以内とする。

### 11.3 エラー分類

エラー分類は、上表を基準として実装する。

複数の条件に該当する場合は、より具体的なエラーを優先する。

例えば、範囲指定の開始行が終了行より大きい場合は `RangeErr` を表示する。

起動時のファイル読み込みエラーは、原因に応じて `Read err` または `Open err` を表示する。

---

## 12. 実装対象外の機能

以下の機能は実装しない。

| 機能 | 理由 |
|---|---|
| 正規表現 | 実装規模を抑えるため |
| 検索 | 初期版では不要 |
| `s` による文字列置換 | 置換構文を省略するため |
| `e` による再読み込み | 編集対象を起動時に固定するため |
| `r` による追加読み込み | 同上 |
| `w filename` による別名保存 | 編集対象を固定するため |
| `u` による取り消し | 変更履歴を管理しないため |
| `k` によるマーク | 初期版では不要 |
| `!` による外部コマンド実行 | シェル連携を省略するため |
| 複数ファイル編集 | 状態管理を簡略化するため |
| 相対アドレス | アドレス解析を簡略化するため |
| マクロ | 初期版では不要 |
| 端末画面制御 | ラインエディタとして不要 |

---

## 13. 受け入れテスト

初期実装では、以下のテストを満たすこと。

### 13.1 起動

- 既存ファイルを読み込める。
- 存在しないファイルを新規ファイルとして編集できる。
- 引数なしで起動した場合、エラー終了する。
- 読み込み権限がないファイルを指定した場合、エラー終了する。
- 空ファイルを正しく扱える。

### 13.2 編集

- `a` で行を追加できる。
- `i` で行を挿入できる。
- `c` で単一行を置換できる。
- `c` で範囲を置換できる。
- `c` で範囲を削除できる。
- `d` で単一行を削除できる。
- `d` で範囲を削除できる。
- 空のバッファに `a` で最初の行を追加できる。
- 最大行数を超える追加を拒否できる。
- 最大行長を超える入力を拒否できる。

### 13.3 アドレス

- 行番号で対象行を指定できる。
- `.` で現在行を指定できる。
- `$` で最終行を指定できる。
- カンマによる範囲指定ができる。
- 範囲の開始行と終了行が逆の場合、エラーになる。
- 存在しない行番号を指定した場合、エラーになる。

### 13.4 表示

- `p` で現在行を表示できる。
- `p` で範囲を表示できる。
- `n` で行番号付き表示ができる。
- `=` で最終行番号を表示できる。
- 空のバッファに対する `=` は0を表示する。

### 13.5 保存と終了

- `w` で編集内容を保存できる。
- 空のバッファを保存すると空ファイルになる。
- 保存成功後は `q` で終了できる。
- 未保存状態で `q` を実行すると終了を拒否する。
- 未保存状態で `Q` を実行すると終了する。
- 保存失敗時には未保存状態が維持される。

### 13.6 エラー処理

- 不正なコマンドを拒否できる。
- 不正なアドレスを拒否できる。
- 不正な範囲を拒否できる。
- 各エラーメッセージが8文字以内である。
- 回復可能なエラーの後も編集を継続できる。

## 14. 仕様上の制約と注意事項

1. 行バッファは固定長であり、上限を超えるファイルは編集できない。
2. 行長はバイト単位で判定する。
3. 正規表現、検索、置換は実装しない。
4. 編集対象は起動時に指定したファイルに固定する。
5. `w` は直接上書き方式であり、原子的な保存を保証しない。
6. `Q` は未保存の変更を確認なしで破棄する。
7. `c` の置換中に容量超過が発生した場合、置換前の内容を自動的に復元する機能は設けない。
8. 保存時にはLFを使用するため、CRLF形式のファイルはLF形式に変換される。
9. 入力行の途中にNUL文字を含むデータはサポートしない。
10. UNIXの `ed` との完全な互換性は目標としない。
