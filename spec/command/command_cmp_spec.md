# 極小UNIX `cmp` コマンド仕様書

| 項目 | 内容 |
|---|---|
| 文書ID | MIN-CMP-001 |
| 版 | 0.1（初版案） |
| 対象 | UNIXサブセットOSの `/bin/cmp` |
| 参照 | UNIX V7 `cmp(1)`、既存OS syscall設計、ilibc APIリファレンス |
| 状態 | 実装仕様案（オプション範囲等は未確定） |

## 1. 目的・方針

2つの入力の内容を**バイト単位**で先頭から比較する。ファイルシステムの読み込み検証、コピーの照合、およびシェルスクリプトの判定に利用する。

- V7の基本動作と終了ステータス（0/1/2）を尊重する。
- 固定長バッファ、動的メモリ確保なし、例外・RTTIなし。
- OS側の `open/read/close/write` システムコールラッパを使う。これらはilibcの機能ではない。
- ilibcの既存文字列関数や書式化APIは必要に応じて使用し、公開APIを増やさない。
- ファイル名のワイルドカード・クォート展開は行わない（シェルの責務）。

## 2. コマンド形式

```
cmp [-s] file1 file2
```

- ちょうど2個のファイルオペランドを要求する。
- `file1` が `-` の場合のみ標準入力(fd 0)を使う。`file2` の `-` は初版では特別扱いせず、通常のファイル名として扱う（V7寄り）。
- 省略可能な `file2`、3個目以降のオペランドは非対応。
- `-s` は診断用の差分メッセージを抑止して、終了ステータスのみを返す。
- `-l`（全差分と8進値の表示）は初版では非対応。将来拡張候補。
- `--`、`--help`、長いオプション、複合オプションは非対応。
- 不明なオプション、オペランド数の不一致、`-s`以外のオプションは使い方のエラー（終了2）。
- `-` に限りオプションではなく第一オペランドとして認識する。

例：

```
cmp /tmp/a /tmp/b
cmp -s /tmp/a /tmp/b
cmp - /tmp/expected
```

## 3. 比較規則

1. 両入力を先頭から順番に1バイトずつ比較する。
2. 同じ位置のバイトが異なる場合、その位置を**最初の不一致**とする。
3. 内容が一致したまま両方EOFに達した場合、一致とする。
4. 内容が一致したまま片方だけEOFに達した場合、不一致とする。
5. NUL、0x80以上、CR、LFも通常のバイトとして比較し、文字コード変換や改行変換をしない。
6. 先頭のバイト番号は1、行番号は1とする。比較済みの先行バイトが `\n` であるたび行番号を増やす。
7. 比較途中にI/Oエラーが起きた場合は、判定不能なエラー（終了2）とする。既に確定した不一致があれば、その時点で終了1としてよい（初版は最初の不一致で比較終了）。

**重要：** `read()` が要求長より少ない正のバイト数を返しても、それはEOFを意味しない。左右の読み取り境界が一致する保証もないため、2つのバッファの位置を独立に管理し、両入力の次の1バイトが揃うまで必要に応じて補充してから比較する。

## 4. 出力仕様

### 4.1 内容一致

標準出力・標準エラー出力とも何も書かない。終了ステータスは0。

### 4.2 最初の不一致（通常モード）

標準出力(fd 1)へ、次の1行を出力する。

```
file1 file2 differ: char N, line M
```

`N`は1始まりのバイト番号、`M`は1始まりの行番号である。表記 `char` はV7/POSIX由来だが意味はバイト位置とする。

例：先頭から4文字目が異なる場合

```
a b differ: char 4, line 1
```

### 4.3 片側EOF

内容が一致したまま片方がEOFとなった場合は標準エラー出力(fd 2)へ以下の診断を出す（`-s`の場合は出さない）。

```
cmp: EOF on file1
```

ここで `file1` は**短い方のオペランド名**に置換する。終了ステータスは1。

### 4.4 `-s` 指定時

内容不一致・片側EOFでも出力しない。通常の使い方エラーやI/Oエラー時も初版では診断出力を抑止し、終了ステータス2のみを返す方針とする（厳密なV7互換とは限らない）。

### 4.5 その他のエラー診断

`-s`を指定しない場合、起動引数エラー、open/read/close失敗、診断出力失敗に対し可能な範囲でfd 2へ簡潔な英語メッセージを出す。正確なerrno文字列は必須としない。診断出力が失敗しても再帰的に再試行しない。

## 5. 終了ステータス

| 値 | 意味 |
|---:|---|
| 0 | 全バイトが一致し、両方EOFまで比較完了 |
| 1 | 最初のバイト不一致、または片側EOF（長さ不一致） |
| 2 | オプション・引数エラー、open/read/close/出力エラーなど |

初版では、必要なcloseを試みた後、closeに失敗した場合は、それまでの比較結果が0でも2とする。不一致が既に確定している場合は終了1を維持する。終了に伴う診断の書き込み失敗は2としてよい。

## 6. ファイル操作

1. `file1`が`-`ならfd 0を使用し、それ以外は`open(file1, O_RDONLY)`。
2. `file2`は`open(file2, O_RDONLY)`。
3. 両入力を比較する。先にopenに失敗した場合も、既に開いたfdはcloseする。
4. 本コマンドでopenしたfdをcloseする。標準入力fd 0はcloseしない。
5. `open()`失敗なら終了2。通常モードではファイル名を含む診断を出す。

ファイル名と内容は書き換えない。通常ファイルのほか、OSの`read()`が可能な入力を比較対象とできるが、無限に続く入力は比較が終了しない場合がある。

## 7. 実装方式とメモリ

- **推奨バッファ：各入力256バイト、計512バイト**。性能要件に応じて512バイト×2にも変更可能。
- 各入力について `{ fd, buffer, valid, pos, eof }` を別々に管理する。
- `pos == valid` になったときのみ次の `read()` を実施する。
- `read()`結果が `>0` ならそのバイト数を保持、`0` ならEOF、`<0` ならI/Oエラーとする。
- 位置カウンタは64bit整数を使用し、ファイルサイズが32bit限界付近でもバイト番号の桁あふれを回避する。表示に必要な整数変換は簡素な専用処理でもよい。
- `memcmp()`は最適化候補だが、行番号や不一致位置の計算を明瞭にするため、初版は1バイト比較でよい。
- メモリは固定長、動的確保は行わない。

## 8. 依存API

| 提供元 | API | 役割 |
|---|---|---|
| OS syscallラッパ | `open()` | ファイルオープン |
| OS syscallラッパ | `read()` | バイト列読み込み |
| OS syscallラッパ | `close()` | 自分で開いたfdを閉じる |
| OS syscallラッパ | `write()` | 差分・エラーメッセージ出力 |
| ilibc | `std::strcmp()` | `-s`および `-` の判定（任意） |
| ilibc | `ilibc::fprint_f<...>()` 等 | 書式付き診断（任意。`%d`/`%s`のみなので64bit位置には注意） |

ilibcの追加機能は不要。なお現行ilibcの書式化テンプレートは`%d`（int）と`%s`、`%%`に限定されるため、64bitカウンタの表示には別途小規模変換を用意するか、出力契約の調整を行う。OS向けI/Oバックエンド実装状態に依存するため、直接`write()`を使用する設計でもよい。

## 9. エラー処理

| 条件 | 挙動 |
|---|---|
| オペランド不足・過剰 | 診断（`-s`時を除く）、終了2 |
| 不明オプション | 診断（`-s`時を除く）、終了2 |
| `open`失敗 | 診断、開いたfdを解放、終了2 |
| `read`失敗 | 診断、開いたfdを解放、終了2 |
| 短い正の`read` | 異常ではない。残りを適切に読み進める |
| `write`が部分成功 | 残りの出力を繰り返す |
| `write`が0または負 | 出力エラー、終了2 |
| 片側だけEOF | 不一致、終了1 |
| `close`失敗 | 診断可能なら出し、正常一致判定を2に変更 |

## 10. 非対応範囲

`-l`、スキップ位置指定、比較バイト数上限、両オペランドの`-`扱い、タイムアウト、シグナル処理、ロケール、巨大整数の書式化API追加は初版範囲外。

## 11. 受入テスト

| テスト | 期待結果 |
|---|---|
| 同内容・同長の2ファイル | 無出力、終了0 |
| 両方空ファイル | 無出力、終了0 |
| 先頭1バイトの差 | `char 1, line 1`、終了1 |
| 途中の差 | 正しいバイト・行番号、終了1 |
| 改行直後の差 | 行番号が1増える、終了1 |
| `0x00`・`0xff`の差 | バイナリとして検出、終了1 |
| 片側が短い | 短い方のEOF診断、終了1 |
| `-s`で差あり | 無出力、終了1 |
| file1が`-` | fd 0とfile2を比較 |
| 存在しないファイル | 終了2 |
| 読み込み失敗の故障注入 | 終了2 |
| 一方の`read()`が毎回1バイトだけ返す | 比較結果が変わらない |
| 一方の`read()`が不規則な短い単位で返す | 比較結果が変わらない |
| バッファ境界直後の差 | 正しい差分位置、終了1 |
| 出力の部分書き込み | 全診断文字列を出力 |
| 出力失敗 | 終了2 |

## 12. 仕様確定前の検討事項

1. `-l`を初版に含めるか（現案は非対応）。
2. `-s`指定時のI/Oエラー診断も無出力とするか（現案は無出力）。
3. `file2`の`-`を標準入力とするか（現案はV7寄りで非対応）。
4. 異常`close()`が発生した際の終了コード優先順位（現案は不一致の1を維持）。
